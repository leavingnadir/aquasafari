🛠️ SSMS Setup Guide — Payment Management

Local SQL Server setup, connection, and dummy data for AquaSafari

This guide walks through installing SQL Server + SSMS locally, connecting it to your Spring Boot backend, and adding dummy customer/booking data so you can test the Payment Management module even if the User Management module isn't finished yet.

1

Install SQL Server (Developer / Express edition)

Download the free edition from Microsoft:

https://www.microsoft.com/en-us/sql-server/sql-server-downloads

  • Choose Express (lightweight, free forever) or Developer edition (full features, free for non-production use).
  • Run the installer → choose Basic installation type for the quickest setup.
  • Note the instance name shown at the end (usually SQLEXPRESS or MSSQLSERVER) — you'll need it to connect.
If prompted, enable Mixed Mode Authentication during setup and set an sa (admin) password — this makes it easier to connect from Spring Boot later using a username/password instead of only Windows Authentication.
2

Install SQL Server Management Studio (SSMS)

Download SSMS separately (it's a free GUI tool, not bundled with the server installer):

https://learn.microsoft.com/en-us/sql/ssms/download-sql-server-management-studio-ssms

Run the installer and accept the defaults — no special configuration needed.

3

Connect to your local instance in SSMS

  1. Open SQL Server Management Studio.
  2. In the "Connect to Server" window:
    • Server type: Database Engine
    • Server name: localhost or localhost\SQLEXPRESS (match your instance name from Step 1)
    • Authentication: Windows Authentication (or SQL Server Authentication with the sa account you set up)
  3. Click Connect.
4

Create the project database

Right-click Databases in the Object Explorer → New Database → name it AquaSafariDB → OK.

Or run this in a New Query window:

CREATE DATABASE AquaSafariDB;
5

Connect Spring Boot to your local database

In backend/pom.xml, confirm the SQL Server driver dependency:

<dependency>
    <groupId>com.microsoft.sqlserver</groupId>
    <artifactId>mssql-jdbc</artifactId>
    <scope>runtime</scope>
</dependency>

In backend/src/main/resources/application.properties:

spring.datasource.url=jdbc:sqlserver://localhost:1433;databaseName=AquaSafariDB;encrypt=true;trustServerCertificate=true
spring.datasource.username=sa
spring.datasource.password=YourPassword123
spring.datasource.driver-class-name=com.microsoft.sqlserver.jdbc.SQLServerDriver

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.SQLServerDialect

Run your Spring Boot app once (mvnw.cmd spring-boot:run). Hibernate will auto-create tables in AquaSafariDB based on your @Entity classes. Refresh the database in SSMS to confirm the tables appear.

If you get a connection error, check that SQL Server's TCP/IP protocol is enabled: open SQL Server Configuration Manager → SQL Server Network Configuration → Protocols → enable TCP/IP → restart the SQL Server service.
6

Add dummy data for Payment testing (no need to wait for User module)

Since payments require a logged-in user and a booking to test against, and the User/Booking modules may not be finished yet, you can insert your own sample rows directly in SSMS to unblock your testing.

Open a New Query window on AquaSafariDB and run something like:

USE AquaSafariDB;

-- Dummy user (only if the users table already exists from Hibernate)
INSERT INTO users (name, email, password, role)
VALUES ('Test Customer', 'testuser@example.com', 'dummy_hashed_pw', 'CUSTOMER');

-- Dummy boat
INSERT INTO boats (name, capacity, status)
VALUES ('Ocean Explorer', 12, 'AVAILABLE');

-- Dummy trip
INSERT INTO trips (boat_id, trip_date, price)
VALUES (1, '2026-09-15', 5000.00);

-- Dummy booking (references the dummy user + trip above)
INSERT INTO bookings (trip_id, user_id, status)
VALUES (1, 1, 'CONFIRMED');

-- Now you can test payment creation against booking_id = 1
Table and column names above are examples — match them to whatever your actual @Entity classes generate. Run SELECT * FROM sys.tables; or expand Databases → AquaSafariDB → Tables in SSMS to see your real table/column names first.
7

Test your Payment endpoints

  1. Run your Spring Boot app.
  2. Open Postman and call your payment endpoint, e.g.: 
    POST http://localhost:8080/api/payments
{
  "bookingId": 1,
  "amount": 5000.00,
  "status": "COMPLETED"
}
  3. Go back to SSMS → run SELECT * FROM payments; to confirm the row was inserted correctly.
8

Clean up before final integration

  • Once the User/Booking modules are ready, remove your dummy rows (or keep separate test data clearly marked) so they don't interfere with the real integrated system.
  • Before the team integration/demo, agree on one laptop's local database to be the shared source of truth, so all six modules are tested against the same data.
  • Keep your real SQL Server credentials out of GitHub — only commit the placeholder template in database/application-example.properties.
